# API inventory

Audit date: 2026-09-03. This is a source-derived inventory of ordered Node HTTP handlers, including legacy/proof entrypoints. It is not a generated OpenAPI contract or a claim every handler was exercised live.

## Reading this inventory

Private canonical requests use gateway port4000 and /api/v1/workspaces/:workspaceId. Public callbacks use the separate real public server4001. :id is the captured resource identifier named by the preceding path segment; braces such as {verify|recheck} list exact accepted alternatives. The original matching expression is retained to disambiguate permissive regex/suffix routing. Query/body field names are observed route reads, supplemented by actual service signatures; TypeScript types are source contracts, not universal runtime JSON validation.

WORKING means a narrowly evidenced implemented handler, not production certification. PARTIAL flags unproven integration, runtime/auth flaws or missing dispatch. MOCK is explicit simulation. LEGACY is retained old entrypoint. UNUSED identifies a handler shadowed by gateway/route order. No endpoint is inferred merely from a page name.

Auth column combines visible route checks with direct service permission references. Absence of an explicit permission is NOT permission to treat the route as public. Platform actor authentication alone is not membership authorization. See chapter14 for confirmed cross-tenant defects. Responses include source HTTP status and exact source return expression where available; follow the linked method/model for complete payload fields.

## Dispatch and shared behavior

Gateway OPTIONS returns204 with configured CORS, and /health proxies platform. Each private module also handles OPTIONS. Governance /health accepts any method before its workspace matcher; it reports hard-coded implementation/release labels, not verification. Gateway child ports4101/4102/4103/4104 are internal; public real server4001 is not a child route.

Known conflicts: platform profile messages and flow-runs are sent to other modules; platform GET/PATCH send-policy is shadowed by delivery POST-only policy; duplicate platform API-key handlers are shadowed by automation; delivery deliverability handlers are shadowed by platform; /segments/rule-registry is shadowed by generic segment detail. Do not bypass authorization by exposing child ports to solve dispatch.

## Exact SNS endpoint

POST https://enjoyable-iphone-zeppelin.ngrok-free.dev/public/v1/provider/ses → public real server4001. Requires the configured SNS topic and valid signature. Supports SubscriptionConfirmation, supported SES Notifications, and a no-op acknowledged UnsubscribeConfirmation. See chapter08 for durable receipt and queue limitations.

## Completeness and limitations

This table covers 225 explicit method/path branches from the inspected route files, plus shared OPTIONS and governance's method-agnostic health described above. One nested proof unsubscribe validation condition is not a separate route. Equivalent paths in separate legacy/real processes are intentionally separate entries. The gateway itself has no product handler beyond health/CORS/proxying.

Body reads omit fields hidden inside helper calls; linked service signatures, packages/contracts/src/phase1 and domain validators are the authoritative continuation points. Source expressions preserve success output shape without inventing DTOs. Main service return data is defined by the models/read-model helpers referenced in chapters05 and23. File line numbers are audit snapshots and may shift after edits.

No public DELETE or real send was executed to validate this inventory. Add gateway-level authenticated contract tests, a machine-readable route registry and bounded runtime request schemas as follow-up work, not another parallel router.
