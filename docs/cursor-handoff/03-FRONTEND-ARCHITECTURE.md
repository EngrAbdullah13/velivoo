# Frontend architecture

## Next application and state

Next App Router pages are under apps/web/src/app. Workspace layout wraps /w/[workspaceId] routes in AppShell; page params are awaited Promises. Most pages are thin server wrappers around client components that fetch after mount. There are 44 authored page files; the build additionally generates a not-found route.

phase1Api uses NEXT_PUBLIC_EMAIL_PLATFORM_API_URL (default http://localhost:4000), no-store and credentials:include. It sends a stored emailPlatformAccessToken as Bearer or a development-user header. phase3Api aliases this client. phase4Api is a separate legacy helper with different env aliases and development-header auth, without the shared Bearer behavior. Consoles generally use local React state/effects, not a shared server-cache/query framework.

The application uses real API data where available; empty/loading/error states are distinct from seeded marketing illustrations. No frontend browser automation suite was found. A successful Next build does not validate clicks, scrolling, sidebar flicker or editor drag/drop.

## Branding and shell behavior to preserve

Full logo: /brand/velivoo-logo.png; compact/fav mark: /brand/velivoo-mark.png. AppShell stores compact state via server-read velivoo-sidebar-compact cookie plus local component state/sessionStorage. Explicit logo opener/collapse buttons change the mode; page navigation must not implicitly expand it. Native anchors still cause full navigations in places, so browser reload/hover behavior needs regression tests.

Menu: Home; Audiences with Contacts (/profiles), Lists and Segments; Marketing/content; Automations/flows; Transactional/deliverability; Analytics; Settings. Compact items have labels/tooltips; grouped navigation should remain usable without changing the sidebar width.

Current final CSS rules in globals.css deliberately match Profiles: Arial,sans-serif forced on body/app-shell descendants; title 31px, 1.15 line-height, weight700 and -.045em spacing; standard body/table cells13px, table headings12px, secondary detail11px. Standard content is full-width white with 10px 22px 44px padding; rounded15px white panels with neutral borders and purple/lime accents. Earlier DM Sans rules remain but are overridden. Do not choose fonts from an earlier selector without checking cascade order.

Fullscreen flow/email/template editor layouts have special containment. Flow inspector appears in the palette area on selection and must not resize the graph away. AppShell topbar/home layout and mobile breakpoint at760px are separate from standard full-bleed pages.

## Aliases, dead UI and integration caveats

/content redirects to /content/templates. settings/users and members are the same member section; audit and audit-log are the same section; settings/launch renders dangerous-actions, not governance/launch-readiness.tsx. Bounces and complaints both render diagnostics. Legacy helper components remain in src/components even when current page wrappers no longer import them.

Profile messages/flow-run panels, send-policy settings and segment rule-registry requests encounter route-dispatch defects. Distinguish these backend failures from a visual implementation gap. Keep API error feedback visible and only clear form inputs or close destructive confirmation after success.
